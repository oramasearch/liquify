# Deterministic UI screenshots

`liquify --screenshot <state> --out <png>` renders one named application state without a visible
display. The screenshot path uses SDL's dummy video driver and software renderer at 1280×800,
with a framebuffer scale of one. It uses the token-derived style and embedded IBM Plex atlas,
static fixture text, and two frames. It reads no repository, clock or network state.

valid name. `--screenshot` and `--out` are required together and cannot be combined with a
repository, `--lake` or `--smoke`.

## Refreshing the proof set

Build the binary, then render the complete registry:

```sh
cmake -S . -B build -G Ninja
cmake --build build -j 6
tools/ui/screenshot.sh
```

Set `LIQUIFY_BINARY` to use another build tree, including the shared libliquid proof build. The
script replaces the named files under `docs/ui/screenshots/`; review the image diff and commit the
whole set. Pull requests that change `src/app.cpp` or a panel attach relevant before and after
images generated by this script.

## Pixel assertions

`tests/ui_pixel_assert.hpp` checks for a color within a bounded pixel region and reports the number
of matching pixels. The screenshot tests render through the same headless application path,
decode the written PNG, and prove that the C++ editor has its selected source row, the diagnostics
panel has its active tab and visible error, and the command palette has its search and recent-list
surfaces. Regions deliberately cover stable layout landmarks rather than whole-image hashes so
harmless rasterizer differences do not hide the intended signal.

The PNG reader and writer in `src/screenshot.cpp` support the generated 8-bit RGBA, non-interlaced
format. PNG chunks, CRC checks and scanline validation are implemented in-tree; the existing zlib
dependency compresses and expands image data.
