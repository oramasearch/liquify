# Tests

`test_repository_view.cpp` creates its readable repository through the pinned `liquid::repository`
API, writes root and nested entries, and proves that `RepositoryView` reads the same on-disk format
it links while leaving nested trees unloaded until requested. It also creates a corrupt
`LIQUID_REPO` marker, checks repository summary metadata, verifies that clone target validation
leaves existing contents unchanged, and checks path and symbol indexes, change annotations, and
context move and new-file refresh.

`test_navigation.cpp` covers file-kind labels, deterministic fuzzy path and definition ordering,
identifier lookup, definition-first references, caller and callee relationships, breadcrumbs,
location history, and unique default bindings for every navigation action.

`test_print_tree_error.cmake` runs the built `liquify --print-tree` command against a corrupt
repository created in the build tree. It requires a non-zero exit and the same liquid error on
standard error. No repository fixture bytes are committed.

`test_version.cpp` checks the public liquify version value and string.

`test_panel.cpp` covers descriptors and commands, placement, focus, hiding, float and re-dock,
default restoration, shared progress, and supported cancellation. `test_app_state.cpp` round-trips
divider sizes, visibility, complete panel layouts, editor split, theme and high contrast through
`.liquid/liquify-state.json`; it also proves version 1 migration, reset, missing state and invalid
state. `test_screenshot.cpp` renders fixed UI states, reads their RGBA PNG output, checks stable
shell regions, and requires panel-system, settings and accessibility themes; the complete visual
matrix is generated by `tools/ui/screenshot.sh`.

`test_input.cpp` exercises the plain-C++ input state machine: Japanese composition and dead-key
cancellation, UTF-8 positions, editor and repository drop routing, rich/plain clipboard forms,
HTML-only paste, reduced-motion duration, and named accessibility controls.

`test_editor_model.cpp` covers configuration-driven indentation, every selection shape, literal
and regular-expression replacement, bracket matching, syntax roles, wrapping and folding.
`test_settings.cpp` covers `.liquid` settings parsing, precedence, validation, reset, search, safe
defaults and credential-free serialization.
`test_editor_buffer.cpp` covers line, selection and multi-cursor edits, UTF-8 cursor movement,
absolute cursor byte offsets, and a save that retains the pending-drip count and reopens the result through
`liquid::repository`. `test_text_layout.cpp` proves cached layouts are reused, an edit invalidates
only its replaced lines, inserted lines preserve following cached layouts, and tabs plus UTF-8
retain byte-to-column positioning.

`test_stub_tree.cpp` parses the checked-in C and C++ declaration fixtures through the public stub
API, checks the exact declaration lists and modifiers, verifies graph persistence and equal-blob
reuse, resolves a declaration across separate stub trees, and proves an edited blob recomputes
without recomputing an unchanged blob.

`test_interactive_analysis.cpp` keeps an invalid C++ fixture open as a volatile overlay and checks
all seven registered analysis queries. It covers closed-file stub hover and definition lookup,
compiler-symbol precedence, translation-unit diagnostics, completion order, local references,
tree-sitter changed-range reuse, cancellation during typing and a successful answer after the edit.

`test_plugin.cpp` registers the sample descriptor statically and loads the same source as a module.
Both paths demand its query through `InteractiveAnalysis`, invoke its command, and decode its panel.
Configuration coverage loads global and repository paths, deduplicates the shared module, and
reports a missing path without losing that module. The suite also refuses a mismatched ABI and
non-canonical CBOR, then proves one panel error does not hide a healthy panel from the same host.
It also installs an ABI-v1 event table and checks that presence, lease, and attribution callbacks
each receive canonical CBOR.

`test_multiplayer.cpp` checks the exact editor labels for presence, lease holders, and per-line
attribution, including the delegated-agent marker, session, and change identifiers.

`test_editor_graph.cpp` proves the application runtime hosts liquid's daemon for the first client,
attaches when a daemon already owns the checkout, serializes overlay mutations, publishes
diagnostics and cursor-query results, records edit-to-diagnostic latency and formats the validation
backlog from daemon status. Its editor-view case loads liquid's real tree-sitter frontend and
checks syntax, attribution, repository search/replace and operation-log undo.

`test_first_run.cpp` covers repository open/switch state, recent-repository persistence, identity
session persistence without credentials, distinct unreadable/offline failures, and the complete
status-bar signal model.

`test_structural_edit.cpp` covers the syntax ancestor selection chain, exact reference ranges,
rename across two files with one drip per file, unresolved string occurrences, stale-fingerprint
refusal, one grouped liquid operation with a two-file undo, compiling C and C++ extract-function
results, deterministic canonical CBOR and the real
headless `--apply-edits` executable path. The extract fixtures use the C and C++ compilers selected
by CMake for syntax-only verification.

`test_review.cpp` runs against libliquid's forge test double. It opens and pulls a review, renders
text hunks, creates a cursor-anchored comment, advances shifted and deleted anchors through a new
head, and verifies approval plus the return to an open requested-changes review.

`test_ai.cpp` verifies the default-off repository and global setting, zero provider constructions
and zero connections against a counting network double, graph-derived context with a byte budget
and explicit omissions, and the Anthropic Messages request over an in-process TLS server. Its SSE
cases cover a normal streamed answer, a refusal stop reason, and a connection ending mid-stream.
It also proves a proposed replacement leaves repository content unchanged until acceptance, then
creates exactly one drip and a local assisted-edit record without recording the prompt.

`test_screenshot.cpp` renders the deterministic C++ editor, complete editor view, diagnostics,
panel-system, settings and accessibility states through SDL's dummy video driver and software
renderer, decodes their PNG output and uses `ui_pixel_assert.hpp` to prove that a highlighted line,
panel title, count badge and high-contrast editor focus ring occupy their expected regions.
